# Портфолио

Astro + Markdown + Pages CMS. Без React, Tailwind и сервера базы данных.

## Запуск

Нужен Node.js версии не ниже 22.12.0.

```sh
npm install
npm run dev
```

```sh
npm run build
npm run preview
```

`dist/` содержит готовый статический сайт.

## С чего читать код

1. `src/content/pages/` — тексты и структура разделов.
2. `src/content.config.js` — допустимые поля каждой страницы.
3. `src/lib/navigation.js` — короткие функции для меню и адресов страниц.
4. `.pages.yml` — поля редактора Pages CMS.

5. `src/components/Menu.astro` — меню и вертикальное название раздела.
6. `src/components/Article.astro` — полноценная статья и дополнительные блоки.
7. `src/styles/global.css` — оформление, мобильная версия и движение.
8. `src/scripts/menu.js` — предпросмотр и управление клавишами.

## Содержание

Папка задаёт вложенность. Файл `ru/about/index.md` — раздел `/about/`, а `ru/about/bio.md` — статья `/about/bio/`. Внутри раздела можно создать новый раздел, например `ru/design/posters/index.md`.

Русский находится в `ru/` и открывается без префикса. Английский находится в `en/` и открывается по `/en/`. Переводы имеют одинаковые пути внутри языковой папки. Переключатель языка сохраняет текущую страницу; если перевод не создан, он ведёт на главную другого языка.

В начале Markdown-файла находятся поля:

```yaml
title: мини биография
kind: article
intro: Короткое вступление.
order: 1
draft: false
```

Далее идёт обычный Markdown. Для раздела используется `kind: section`, его файл должен называться `index.md`. Переименование файла меняет URL, изменение `title` — только надпись.

### Markdown внутри статьи

В Pages CMS у поля «Текст» есть вкладки Editor и Source. Для полного Markdown, включая таблицы, сноски и списки задач, используйте Source. Изображения можно загрузить в Media и вставить в текст:

```markdown
![Описание изображения](/images/photo.jpg "Необязательная подпись")

https://example.com/page

[Обычная текстовая ссылка](https://example.com/page)
```

Изображение отображается прямо в статье; строка в кавычках становится подписью. Отдельный URL в своём абзаце превращается в предпросмотр с заголовком, описанием и картинкой страницы. Ссылки с заданным текстом остаются ссылками, даже если текст тоже выглядит как URL.

Данные предпросмотра загружаются только при сборке. Если сайт не отвечает за 4 секунды или не отдаёт метаданные, остаётся блок с адресом; это не прерывает публикацию. При недоступности картинки сохраняются текст и ссылка. Изображения и описания зависят от данных, опубликованных владельцем страницы.

Поддерживаются заголовки, выделения, зачёркивание, вложенные списки, списки задач, цитаты, таблицы, разделители, сноски и блоки кода с подсветкой. Обработка Markdown и карточек — `src/lib/article-markdown.js`, получение метаданных — `src/lib/link-preview.js`.

В редакторе также доступны галерея с подписями, видео MP4/WebM, блок кода, ссылки, дата, время чтения, оглавление и следующая статья. Изображения можно вставлять и прямо в текст. Блоки кода в Markdown оформляются тройными обратными кавычками. Оглавление строится из заголовков текста. Необязательные блоки не отображаются, пока их не заполнить.

Для видео Cloudflare Pages ограничивает один файл 25 МиБ: крупное видео разместите на отдельном файловом хостинге и укажите прямую HTTPS-ссылку. В поле «Видео YouTube / Rutube» можно вставить ссылку на видео; сайт сам создаёт встраиваемый плеер.

Имя и Telegram редактируются в «Имя и контакты». Тексты сейчас — примерное наполнение для проверки макета, а не подтверждённая биография; замените их перед публикацией. Названия vexd и work space взяты из Figma, описания результатов этих проектов не придуманы.

Черновики и дети чернового раздела исключаются из опубликованного сайта. В публичном GitHub-репозитории файлы черновиков всё равно видны; для личных материалов используйте приватный репозиторий.

## Cloudflare Pages

1. Создайте GitHub-репозиторий с содержимым этой папки в корне.
2. В Cloudflare выберите Workers & Pages → Create → Pages → Connect to Git.
3. Команда сборки: `npm run build`. Выходная папка: `dist`.
4. Установите `NODE_VERSION` в `24` (поддерживаемая LTS-версия).
5. Домен подключается в Pages → Custom domains. Для корневого домена нужны NS Cloudflare; для поддомена можно использовать CNAME у другого DNS-провайдера.

Проект статический: адаптер Cloudflare, Worker и секретные ключи для сборки не нужны.

## Pages CMS

Откройте https://app.pagescms.org/, войдите через GitHub и разрешите приложению доступ только к репозиторию сайта. Файл `.pages.yml` уже содержит конфигурацию редактора. После сохранения Cloudflare Pages автоматически пересоберёт сайт через Git-интеграцию.

Репозиторий: https://github.com/romariob10/portfolio (ветка `main`). Pages CMS уже имеет к нему доступ. Исходный шаблон AstroPaper сохранён в ветке `codex/astropaper-backup-2026-10-13`.

Прямой вход в редактор: https://app.pagescms.org/romariob10/portfolio/main/collection/pages. После обновления страницы появятся «Имя и контакты» и «Разделы и статьи». Коллекция показана деревом; язык и вложенность определяются папками, разделы — файлами `index.md`.

Сайт: https://portfolio.rodev.cc/. Резервный адрес: https://romariob10-portfolio.pages.dev/.

Проект Cloudflare `romariob10-portfolio` связан с `main`: `npm run build`, выход `dist`, `NODE_VERSION=24`. Поддомен активирован, HTTPS включён. Cloudflare-приложению разрешён доступ только к репозиторию `portfolio`.

Сохранение мини-биографии через настоящую Pages CMS проверено: редактор создал коммит, Cloudflare автоматически запустил сборку. Пустая дата остаётся пустой; задайте её явно, если хотите показать дату публикации.
